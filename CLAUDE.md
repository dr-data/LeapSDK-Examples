## Teacher Monitoring & Sync Architecture

### Role System
- **Admin** (2 seed accounts: admin01, admin02) - manages teachers, global config
- **Teacher** - manages students, views dashboard, monitors conversations
- **Student** (default role) - chats with AI, must sync conversations

### Authentication
- All users authenticate with classcode + password
- Student classcodes: format `YYfNNN` (e.g. `26f327` = year 2026, form 3, student 27)
- Passwords randomly generated by creator (admin creates teacher, teacher creates student)
- Session persisted in Keychain, SwiftData stores accounts

### Sync Architecture
- **Hybrid**: Bonjour (LAN) primary, cloud REST API fallback
- **Delta sync**: Only unsynced messages transmitted
- **Batching**: 50 text / 10 image messages per batch
- **Thumbnails**: 200px JPEG at 0.5 quality (not full images)
- **Protocol**: REST over HTTP with JSON + multipart for images

### Force Sync Gate
- Blocks student from chatting when thresholds exceeded
- **Message threshold**: configurable (default 10 unsynced messages)
- **Time threshold**: configurable (default 1 hour since last sync)
- Enforced at `ChatStore.send()` (synchronous check) + UI level

### SwiftData Schema
- `UserAccount` - user identity and roles
- `SyncableMessage` - messages with sync status tracking
- `ChatSessionRecord` - conversation metadata with denormalized unsynced count
- `SyncConfiguration` - teacher-configurable sync thresholds
